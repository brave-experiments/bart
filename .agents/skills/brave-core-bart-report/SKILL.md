# Report Brave Android work

Produce the requested result from intended behavior, build/source identity, actual observations and retained evidence. Select a local development summary, assessment, technical review, investigation summary, prototype demonstration or draft PR using [reporting](../../../docs/reporting.md). Resolve links from this skill's real source directory through any discovery symlink.

Honor the requested format and location. For local HTML with captures, follow [HTML verification delivery](../../../docs/reporting.md#local-html-verification-report), including relative local media/receipts and a truthful report for blocked or partial outcomes.

Use its [HTML structure example](../../../docs/examples/qa-report.html) for readable evidence packs with inline captures. Theme- and orientation-dependent bugs require [theme](../../../docs/evidence.md#theme-change-bugs) or [rotation demo video](../../../docs/evidence.md#orientation-change-bugs), or an explicit capture blocker/incomplete transition result; do not substitute screenshot links silently.

For QA verification, lead with the [verification summary](../../../docs/reporting.md#verification-summary-format): outcome emoji/headline, unofficial notice, compact device/build identity, STEPS, ACTUAL RESULTS and labeled SCREENSHOT / SCREENCAST media. Put detailed receipts and check matrices after that summary.

For technical review, use the [findings-first review format](../../../docs/reporting.md#technical-review-report), distinguishing runtime-reproduced findings, source-only findings and hypotheses. Reuse the HTML example's presentation structure without imposing a QA pass headline on the review.

For published QA reports or local reports intended for publication, prepare the [text-only context attachment](../../../docs/report-context.md) from useful retained commands, instructions, test inputs and sanitized receipts. Use its unique filename convention; exclude media/binaries and do not add a live replay merely to create the export.

Use current conversation and saved evidence. Inspect decisive media using [evidence guidance](../../../docs/evidence.md); a referenced file or successful command is not a behavior assessment. Keep observations, attribution, coverage and delivery status distinct. Missing footage remains missing; do not invent a transition or rerun the app just to regenerate prose.

If evidence raises a new question, return to source investigation or request-scoped observation as useful. Report an honest limit when more work is unavailable or outside scope. Include relevant failed/mixed attempts and omitted checks.

When publication is requested, follow [delivery scope and publication](../../../docs/reporting.md#delivery-scope), including independent QA/PR destinations, explicit overrides and preview semantics. Return an inspectable local assessment when posting is not requested. Complete remote delivery with confirmed accessible links, or retain the draft and state the precise blocker. Use the host's authorized tools, not another agent launcher.
